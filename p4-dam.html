The problem

Front-end developer capacity on my product dropped from six to two. Competitors were growing and hiring, and we still had to deliver as many features without lowering quality.

Role and team

I designed features and shipped production front end. My PM set priorities and tracked feature output, using his own agentic system to pull feedback from the repository. The two front-end developers reviewed my code and built the rest. I built the skills and agents that write the specs and handovers.

Key decisions

I gathered context first, then wrote a spec an AI could use

For each feature I work with my PM and his agentic system, which pulls feedback from the repository. I ask a fixed set of questions and capture the answers in note-taking apps, then build a spec file an AI can use. More context up front means I deliver features faster.

I worked in the real product code instead of screens

I push to branches, take code review and match the same standards as our senior developers.

I decided against the old way of designing in Figma and handing screens over. With two developers left, that handover would have become a bottleneck, and we could not hire or bring in other teams. We had to work with the people we had.

I built skills and agents to write the handover

They generate spec files, handover documents and a snapshot file that captures the UI in every state. The developers’ own AI tools can build from those, and the developers can see exactly what the design looks like on my screen, so they know what to expect.

Planning meetings for a feature now take about 30 minutes. They used to take about an hour, every Tuesday and Thursday. Fewer handover questions is why.

Shipped

One of the features I released was realistic lighting in P4 DAM. I replaced the flat grey background in the asset viewer with switchable image-based environments, so 3D assets actually pop, and users and reviewers can judge shape, materials, and quality in realistic lighting.

The result

We released 25% more features than six months earlier. The figure comes from my PM’s tracking.

The work produced several skills and workflows. One has me ask my PM specific questions on a live call and turns the transcript into structured data. It became a Claude skill, which we presented at the company hackathon. It won Best Designed, and I got a prize. Other teams and designers in the business now use it.

How I used AI

Before, I worked from Figma files, documentation and a design system, and spent a lot of time with developers in planning meetings. Now the specs and the handover I built cut that time down. Claude gets things wrong: on the lighting feature it used the wrong components, and I rewrote the CSS by hand.

Looking back

I would talk to the developers more. I built many of the tools they needed on assumptions. It worked well, but I later found gaps in the new spec files that a conversation at the time would have resolved on the spot.

Cut automation complaints from 8 to 10 a month to zero by redesigning an open-source workflow builder around a 25-user study

I ran a paid study with 25 users, presented the findings to the CEO, CMO and Head of Engineering, and redesigned the automation builder so every step shows its data and errors. Budibase later built its AI agents feature on top of it.
